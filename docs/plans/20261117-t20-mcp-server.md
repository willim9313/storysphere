# T20 MCP server 規劃（2026-11-17，使用者確認）

依據：04 §5、01 §8。範圍：04 §5.2 的 14 個工具、`trace_calls`、`not_in_trace`、`create_note` 只產生草稿。

## 現況

- 讀取工具在 REST 已有對應查詢（`api/queries/`）；方法引擎已支援 `agent_session_id`；`write_evidence`、`assert_no_system_fields` 已在。
- `mcp` 2.3.0 已是間接依賴；T02 spike 的 `MCPServer`＋Bearer 驗證可沿用。
- N-04a 觸發、N-05c trace、N-05d 段落的邏輯寫在 route handler 裡，要先抽到 `api/queries/` 讓 MCP 共用（04 §6.2：MCP 不經 HTTP，共用服務層）。
- `agent_sessions`、`trace_calls` 兩張表未建；Gateway、session 端點、確認端點在 T25。

## 實作決定（04 沒寫的）

1. **session 識別**：建 `agent_sessions`、`trace_calls`（01 §8、04 §5.6）。MCP 收到 Bearer token 比對 `token_hash`。目前的 `turn_id` 與該輪使用者訊息（草稿的 `question`）放在記憶體的 `SessionContext`，由 T25 的 Gateway 更新；T20 只提供 `set_turn()`。
2. **`add_interpretation` 的確認**：`Approver` 介面；發 `approval_request` 後等一個 Future，`resolve_approval(request_id, allow)` 留給 T25 的端點呼叫。T20 測試用假 approver 驗兩條路（允許→寫入、拒絕→`approval_denied`）。
3. **AgentEvent 去處**：發到 `EventBus` 的 `session:<id>` 串流（`tool_call`、`tool_result`、`view`、`note_draft`、`approval_request`）。session 的 SSE 端點（N-10）留給 T25。
4. **`create_note`**：草稿存 `agent_sessions.drafts_json`；`check` 套筆記規則（第 1 層、`rejected` 不能引用）。確認寫入（N-06c）不在 T20。

## 分批

- **A 批（主對話）**：`store/agent.py`（兩張表＋存取）；`mcp/server.py`（MCPServer、Bearer 驗證、trace 包裝、錯誤 `{code, message, hint}`）掛到 `api/main.py` 的 `/mcp` 併入 lifespan；共用邏輯從 route 抽到 `api/queries/`；`uv add mcp`。
- **B 批（subagent）**：`mcp/tools_read.py` 讀取 8＋分析 2 個工具，照 04 §5.3／§5.4 轉 snake_case、截短，每個工具有測試（in-memory MCP client）。
- **C 批（主對話）**：`mcp/tools_write.py` 寫入／呈現 4 個工具（`not_in_trace`、草稿、確認、`show_view`）；HTTP 層測試驗 token 錯回 401。

## 還原

每批各自 commit；`var/` 不碰；測試全用 `tmp_path`＋mock。
