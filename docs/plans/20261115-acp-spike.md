# ACP spike：從 Python 經 ACP 驅動 Claude Code（T02）

2026-11-15 · 對應 `docs/spec/07` T02、`docs/spec/05` §5.2

## 結論

**可行。** Python 端用官方 `agent-client-protocol` SDK 啟動 `claude-agent-acp`，建 session 時傳入 StorySphere 的 MCP server，大腦能呼叫工具，Python 端收得到 tool_call 與結果、能關掉內建工具、能攔下 permission request。不需要啟用備案（Claude Agent SDK）。

但 **adapter 的預設值不安全**，要達到「大腦只經 MCP 碰系統」必須明確設三件事（見「必要設定」）。只照 05 §5.2 的描述接上去而不設這三件事，Bash 與寫檔會在沒有任何詢問下直接執行。

## 環境

| 項目 | 版本 |
| --- | --- |

| ACP 協定版本 | 1 |

腳本：`scripts/acp_spike/run_spike.py`、`scripts/acp_spike/ping_mcp_server.py`。

```bash
uv run --with agent-client-protocol --with mcp --with uvicorn python scripts/acp_spike/run_spike.py
```

## 完成標準

| 標準 | 結果 | 證據（第二次執行） |
| --- | --- | --- |
| 收到 tool_call 與結果事件 | 通過 | 情境 A：`session_update` 收到 `tool_call`（`mcp__storysphere__ping`，pending）→ `tool_call_update`（completed，`{"result":"pong: hello-from-spike"}`）；MCP server 端記到 `ping('hello-from-spike')`，所有 HTTP 請求都帶對的 Bearer token |
| 能關掉 Bash、寫檔工具 | 通過 | 情境 B：`tools: []` 之下大腦回報唯一可用的工具是 `mcp__storysphere__ping`；沒有任何 Bash／Write 的 tool_call；工作目錄沒有產生檔案 |
| permission request 能在 Python 端攔下 | 通過 | 情境 A 允許一次 → 工具執行；情境 C 拒絕 → `tool_call_update` 為 failed「User refused permission to run tool」，MCP server 沒收到第二次呼叫；情境 D（保留內建工具）Bash 與 Write 各送一次 permission request，拒絕後都 failed，沒有產生檔案 |

## 必要設定

第一次執行沒有加這些設定，結果是：**permission request 一次都沒送到 Python 端**，情境 C 的 ping 與情境 D 的 Bash、Write 全部直接執行（工作目錄真的出現 `bash2.txt`、`write2.txt`），而且大腦看得到使用者帳號的連接器工具（Claude Docs 等）。原因與對策：

| 問題 | 原因 | 對策（已實測有效） |
| --- | --- | --- |
| 沒有任何 permission request | adapter 沒被指定模式時，初始權限模式選 `auto`（由分類器自行放行），不是逐次詢問 | 建 session 後立刻 `set_session_mode(session_id, "default")`。之後每次工具呼叫都會送 `session/request_permission` |
| 使用者的個人設定進到 session | adapter 預設 `settingSources: ["user", "project", "local"]`，會載入 `~/.claude` 的允許規則、預設權限模式、MCP server | `new_session` 的 `_meta.claudeCode.options` 傳 `settingSources: []` |
| 帳號的連接器工具漏進來 | Claude Code 會自動帶 claude.ai 帳號上的連接器 | `_meta.claudeCode.options.extraArgs` 傳 `{"strict-mcp-config": null}`，只留 session 傳入的 MCP server |
| 內建工具 | 預設是完整的 `claude_code` 工具組 | `_meta.claudeCode.options.tools: []`（比 `disallowedTools` 黑名單安全：新版多出來的工具不會漏網） |

Python SDK 的 `new_session(**kwargs)` 會把多的 keyword 放進 `_meta`，所以寫法是：

```python
await conn.new_session(
    cwd=workdir,
    mcp_servers=[HttpMcpServer(type="http", name="storysphere", url=..., headers=[HttpHeader(...)])],
    claudeCode={"options": {"tools": [], "settingSources": [], "extraArgs": {"strict-mcp-config": None}}},
)
await conn.set_session_mode(session_id=..., mode_id="default")
```

## 對 T26 的含意

- **Gateway 的 L0 要由三層一起保證**：`tools: []`（沒有內建工具）＋隔離設定（沒有外來工具與允許規則）＋`default` 模式（每次呼叫都問）。少任何一層都有洞。
- **MCP 工具呼叫也會觸發 permission request**。讀取與分析類要自動放行（04 §5.2），所以 Gateway 的 `request_permission` 處理要依工具名分流：白名單內的 StorySphere 工具直接回 `allow_once`，需確認的轉成 UI 的 `approval_request`，其餘一律拒絕。不要回 `allow_always`，否則 harness 會記住、之後不再問。
- **工具名**：大腦看到的是 `mcp__<server 名>__<tool>`；`tool_call` 事件的 `_meta.claudeCode.toolName` 有完整名稱，`title` 會在後續 update 變成人看的描述，不能拿 `title` 判斷是哪個工具。
- **`tool_call` 初始事件的 `raw_input` 是空的**，參數在後續的 `tool_call_update` 才出現。04 §5.1 規定 trace 與 AgentEvent 只從 MCP server 端發，這個做法是對的，不必依賴 ACP 事件的內容。
- **adapter 會送 `auth/status_update` 通知**，Python SDK 1.0.0 的 router 不認得，會在 stderr 印「Method not found」的 traceback。不影響運作，T26 要接掉它（也可用來偵測未登入）。
- **未登入時**：`initialize` 與 `new_session` 都成功，到 `prompt` 才回 `RequestError: Authentication required`。05 §6 的大腦測試要用一次真的 `prompt`（或 `claude auth status`）才測得出登入狀態。
- **環境變數**：spike 直接繼承呼叫端的環境。Gateway 應照架構文件用白名單（`HOME`、`PATH` 等），不要把後端的金鑰傳給子 process。

## 沒有驗證的

- `permission_mode` 能否在建 session 時就指定（目前是建好後再切，中間有極短的 `auto` 視窗，但那時還沒送任何 prompt）。
- 使用者在對話中要求大腦切換模式時會不會成功（`available_modes` 含 `bypassPermissions`）；T26 要確認 Gateway 能擋下或還原。
- Skills 寫進 `.claude/skills/` 的注入方式（05 §5.2）。注意 `settingSources: []` 可能連帶讓專案層的 skills 不被載入，T26 要實測。
- 串流文字的切塊粒度、取消（`cancel`）、長時間工具呼叫。
- adapter 是經 npmmirror 下載的（當時這台機器連不到 npm 官方 registry），沒有用官方來源重驗。

## 花費

兩次完整執行（各 4 輪短對話）＋兩次因未登入而失敗的啟動。每輪 5–11 秒，單次執行約 35 秒。token 用量 adapter 沒有回報在這次記錄的事件裡，未統計。
