### 1. B-092 `ConceptInferencePipeline` 從未接線 🟡

**已組裝的 99 筆 TEU 全數少了一整段證據**，而且沒有任何跡象告訴使用者。
`tension_service.py:879` 的 `if inferred:` 分支從誕生至今沒進去過；全 DB 470 筆實體
`extraction_method` 全是 `ner`、`inferred` **0 筆**。

排第一是因為它**不是「還沒做的功能」，是正在污染既有產出**——每一筆 TEU 都是在缺
一段證據的情況下生成並被審核的。成本極低：整本書**一次** LLM 呼叫。

**動工前必須先修截斷 bug**：`concept_inference` 蒐集「候選事件所在章節的全部段落」
後硬截前 12,000 字元。《大唐雙龍傳》彙集 39,998 字元只送出 12,000，**丟棄 70% 且丟的
一律是後段**。不先修，「接上去能提升品質」這個假說連公平驗證的機會都沒有。

**需要決定**：要不要照 F-01 加側存 + pending/confirm（推斷出的 concept 進不進 KG、
要不要人工確認）。這是產品決定。

### 2. B-068 事件抽取把同一場戲切成多個 event 🟡

《名字的潮汐》ch3 有三則 TEU 描述同一場戲，來自**三個不同的 `event_id`**。審核者讀成
三重佐證，實為一場戲的三次改寫；TEU 密度圖被灌水；所有以 event 數為基礎的統計都偏高。

排第二是因為它是**資料層的重複**，往上污染每一個消費者，而且**人看不出來**——三筆
看起來就是三筆。比 B-092 難修：`Event` 目前只有 `chapter` 與 `narrative_position`，
沒有 chunk / scene 錨點，可靠去重可能得先補欄位。

**與 B-069 的關係**：張力證據「同場景摺疊」的判準已驗證失敗並擱置，等的就是這一張。

### 3. B-100 token 歸屬修好之後沒有任何資料驗證過 🟢

B-081 標 ✅ 完成、也加了 AST 掃描測試防回歸，但**那個測試驗的是「呼叫點有沒有設
context」，不是「資料庫裡真的有歸屬」**。`var/token_usage.db` 最後一筆是 2026-08-19
11:49，而最後一次修正是 08-20——**修好之後一筆新資料都沒有**。

排第三是因為**成本近乎零**（下次跑任何分析後查一行 SQL），但它決定「Token 用量頁的
分書數字可不可信」。而且這正是這輪反覆撞到的形狀：**宣告與現實之間差一次實測**。

```sql
select service, count(*), sum(book_id is not null)
from token_usage where ts > <該次分析的時間> group by service;
```

### 4. B-065 各功能頁操作說明缺乏統一機制 🟡

9 個功能頁只有 2 頁有常駐操作說明，且是兩套各自實作的元件。條目裡記了一個具體案例：
時間軸頁「倒敘與預敘」被覆蓋率擋住時，提示叫使用者去事件分析頁補 `story_time_hint`
——**但那個欄位在抽取階段就決定、事件分析不會改變它**。提示本身是錯的，而想更正時
發現無處可放。

排第四是因為它是**唯一一張會讓使用者做出錯誤操作**的票（照著提示跑一次不會有用的
分析，付了 token）。影響面比前三窄，但那是使用者直接踩到的。

**注意這是規範先行的任務**，不是逐頁補文案：先有放置準則與可重用元件，再談各頁內容，
否則會重演「想補說明卻沒地方放」。

### 5. B-072 張力 Step 1 失敗的 TEU 無清單 🟢

`{{assembled}} / {{candidates}}` 兩數不等時只亮一個警告旗標，**看不到哪些場景失敗、
為什麼**。前置已查明：`_assemble_one` 的 except 只 `logger.warning`，後端**沒有留任何
清單**，要從服務層改起。

排第五是因為它與批次 EEP 的失敗處理是**同一個形狀**（`failed += 1` 然後繼續、不留
清單），修的時候應該一起收——那個形狀在走查 B-096 成因時也撞到過。

## 五、這輪學到、下一輪要帶著的

- **不要把掃描器說的當成事實**——這句話在上一份計畫寫過，這輪又應驗第三次，而且是
  唯一一次「照著做了才發現錯」。刪除類任務的驗證順序應該是：靜態掃描 → **執行期實測**
  → 才 commit。i18n 那次若沒跑瀏覽器，12 個裸 key 會直接進 main。
- **只驗看得到的那幾頁不夠**。i18n 誤刪的 12 個裡，瀏覽器只抓到 3 個；另外 9 個
  （象徵頁空狀態、張力頁排序）當時沒出現在畫面上，是回頭用同一個判準重掃才找出來的。
- **閘門不可接管線**。`pytest | tail` 的 exit code 是 tail 的，踩過一次假綠。每道
  各自跑、當場印 `$?`。
- **「暫緩」要附有效期會過期的理由**。`get_fallback` 當初記「等 B-075」，B-075 結案後
  那個理由就失效了，於是這輪重新翻案一次。現在的理由（跨雲是懸而未決的產品問題）
  不會過期。
- **失敗要留清單，不只留計數**。`failed += 1` + `logger.warning` 這個形狀在批次 EEP、
  TEU 組裝兩處都有（B-072），事後完全無從得知是哪幾筆。
