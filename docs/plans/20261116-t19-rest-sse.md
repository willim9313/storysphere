## 程式結構

| 位置 | 內容 |
| --- | --- |
| `api/main.py` | lifespan：能力檢查 → engine、`init_db` → `mark_interrupted_jobs` → checkpointer → `IngestService`、`MethodEngine`、`MethodJobs`；全部掛在 `app.state` |
| `api/deps.py` | 從 `app.state` 取 session、registry、各 service 的 FastAPI 依賴 |
| `api/errors.py` | `ApiError(status, code, detail)` 與 handler；FastAPI 預設的 422、404 也轉成 `{detail, code}` |
| `api/schemas/` | camelCase 的回應 model（`alias_generator=to_camel`）；不直接回 domain model |
| `api/routes/<群組>.py` | 一個端點群組一個檔：`books`、`ingest`、`overview`、`runs`、`evidence`、`registry`、`settings`、`jobs` |
| `api/queries/` | 唯讀查詢（證據列表、追溯、view 資料、run 的推得欄位）；T20 的 MCP 讀取工具共用這一層（04 §6.2） |
| `api/events.py` | SSE 的事件緩衝（B 批） |

## 04 沒寫的決定

- **資料庫路徑**：環境變數 `STORYSPHERE_DB`，沒設就用 `var/neo.db`。checkpoint 檔路徑用 `STORYSPHERE_CHECKPOINT_DB`，沒設就用 `var/ingestion_checkpoints.db`。測試一律指到 `tmp_path`。
- **證據內容的 camelCase**：`content`、`genreExt.data` 是依類型變動的 dict，用一個遞迴轉 key 的函式處理；以資料當 key 的欄位（`centrality`、`chapter_distribution`、`intensity_by_chapter`、`attributes`）內層不轉（04 §1.1）。這些欄位在 openapi 裡是 `object`，前端沒有逐類型的型別。
- **cursor**：`offset` 的 base64，不透明。原型資料量小，不做 keyset。
- **`q` 少於 3 個字**：FTS5 trigram 搜不到，退回對 `summary` 與引文做 `LIKE`；3 個字以上走 FTS，使用者輸入整串包成一個 phrase（雙引號跳脫）。
- **時間**：SQLite 讀回的時間補 UTC，輸出結尾 `Z`。
- **SSE 緩衝**（B 批）：行程內一個 `EventBus`，每條串流（每個 job、每本書）一個 `deque(maxlen=1000)` 與遞增 seq；發事件時同步把 `jobs.last_seq` 寫回。訂閱者各有一個 `asyncio.Queue`。伺服器重啟後緩衝清空，帶舊 seq 來的連線收到 `resync`。service 層（`IngestService`、`MethodJobs`）收一個選填的 `emit` callback，不直接依賴 `api/`。
- **取消**（B 批）：背景工作用 `asyncio.Task` 跑，`app.state` 留 job id → task 的表；取消＝`task.cancel()`＋把 job 標 `cancelled`、執行中的單位退回 `pending`、刪該 thread 的 checkpoint。
