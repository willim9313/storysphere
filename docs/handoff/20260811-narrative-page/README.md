## ⚠️ 這次不是「把版面重畫一次」

與前幾頁的翻新不同：**這頁的視覺語言品質是好的**。四種視圖、三相位分組、
信心量表、雙主題都成立，不需要推倒。截圖是為了理解現有功能與資料密度。

真正要解決的是三件事（brief §1）：

1. **沒有定位** —— breadcrumb 之後直接是兩張視覺權重相同的卡，而它們是不同性質的東西：
   「英雄旅程」是**詮釋**、「情節骨幹摘要」是**統計**。頁面沒表達關係與閱讀順序。
2. **最關鍵的解讀指引被當成註腳** —— 「缺席的階段是有意義的敘事選擇，而非『未完成』」
   目前是灰色最小字級。讀不到這句，使用者只會把缺席理解成分析壞了。
3. **有一半的設計在真實資料下不成立** —— brief §3 全節。

**硬約束只有三條：**

1. **token 不新增、既有值不改。** 怎麼用完全開放；若確實需要新 token 請明確指出。
2. **雙主題 Warm + Ink，皆淺底**，兩套都要出。
3. **不新增任何 API endpoint。** 所有區塊都複用現有資料，`sample-payloads/` 即全部可用素材。

brief §3 的資料陷阱是**必須解決的問題，不是工作範圍的邊界**。

## 給設計側的五個重點（詳見 brief）

1. **§1 主軸：第一次進來的人不讀任何段落，就要能答出「這頁有哪幾塊、先看哪塊、
   每塊在講什麼、看到的數字算好還是不好」。** 先讀這節。
   推論出的硬約束：**可讀性由版面承擔，不由文案承擔**——需要靠加一段說明才能懂的版面，
   就是還沒設計完。新增文字總量應不超過因此被移除的量。

2. **§3.1 階段順序 ≠ 章節順序** —— 直接決定設計成立與否：
   - 第 4 階段「遇見導師」ch1–2 **整段早於**第 3 階段「拒絕召喚」ch2–4
   - **三個階段共用完全相同的 ch1–2**；另三個擠在 ch9–10
   - **任何把 12 階段畫成單調時間軸的設計都會說謊。** 現行「章節對位帶」有效正是因為它讓這件事看得見。

3. **§3.2 三態視覺語言實測只有一態會出現** —— 信心全部 ≥0.8（`low` 從未觸發），
   `absent` 因後端省略而從未出現。修好之後是**兩態**：飽和的已識別 + 少數缺口。
   不要為三段連續梯度設計精緻區分——**那個缺口才是全頁最該被看見的東西**。

4. **§3.3 + §3.6 兩種極端都要撐住** —— 每章 2～7 個 kernel 事件（`名字的潮汐`）
   與只有一章有事件（`大唐雙龍傳`）。現行軌道**在兩種資料下都失效**。
   而且空狀態是常態：時序分析兩本書都沒跑過，所以 §4-E、§4-F 兩張新卡片
   **未分析態才是它們的預設外觀**，請先設計那個樣子。

5. **§3.4b 代表事件的兩個副作用** —— 第 12 階段拿到 **0 筆**（kernel 事件止於 ch9），
   第 1、2、4 階段因共用 ch1–2 而拿到**完全相同的 4 筆**。
   這不是瑕疵而是資料真實形狀：階段是章節級、事件是章節內，本來就不是一對一。
   怎麼誠實呈現是 §7.5 的開放問題。

## 這頁的使用者是誰

**閱讀分析者，不是一般讀者。** 他要回答的是「這本書的敘事弧長什麼樣、哪些事件撐起它、
系統的判斷可不可信」。與鄰頁的邊界：事件分析頁回答「這個事件是什麼」、
時間軸頁回答「事情按什麼順序發生」、張力頁回答「衝突怎麼起伏」——
本頁回答「**整本書的結構是什麼形狀**」，是這幾頁之上的一層俯瞰。

因此本頁不重做事件清單、不重做時間軸；引用它們時一律深連結過去。

## 示範資料的使用方式

canvas 裡出現的人名、章號、事件標題、座標、數值，**實作端一律即時從真實資料計算，不寫死**。
請不要把版面設計成只有在特定筆數下才成立的樣子——brief §3 的每一個極端案例
（每章 7 個事件、只有一章有事件、三個階段同章、整本 0 階段、最後階段 0 事件）都要能撐住。

## 尚未定案、需要設計側一起回答的問題

見 brief §7。其中三題最關鍵：

- **預設視圖是否從「水平軌跡」改為「章節對位帶」？**（§7.1）實測對位帶最能一眼看出
  階段與章節的對位、重疊與逆序，而目前的預設恰好是資訊密度最低的一個。
- **兩張卡是否維持上下堆疊？**（§7.2）詮釋與統計的關係也可能適合並置或交錯。
- **代表事件重複與缺空怎麼呈現？**（§7.5）去重、標示「與前一階段共用」、還是照實列出？
