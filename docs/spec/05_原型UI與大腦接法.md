# 05 原型 UI 與大腦接法

## 1. 目的與範圍

原型 UI 是**檢視器**：看新版後端的產出是否符合契約，並能接上 agent 大腦做提問。不是新版正式前端，也不搬既有九個書籍頁。

成功條件：

1. 用 `storysphere_benchmark` 的推理文本（`01_推理_四簽名`）跑完入庫，UI 能看到每個步驟的產出與失敗單位。
2. 自動觸發的 10 張結果卡都能打開、看到 view、展開證據、追溯到原文。
3. 同一個問題分別用 deepagents（Gemini）與 Claude Code 回答，都能產生筆記草稿、確認後存成筆記，且筆記能重跑（架構文件階段二的通過條件，原型提前驗證）。

原型決定：

- 介面只做繁體中文（既有產品要求中英並重，原型先不做 i18n）。
- 桌面寬度 ≥ 1024px；不做窄版。
- **開發者檢視**：設定頁有開關，打開後可看第 1 層證據與原始 trace。契約 v2 規定一般使用者看不到第 1 層，原型要驗證抽取品質，所以預設打開，正式版關掉。

### 3.3 Agent 工作區

左邊是對話，右邊是「本次分析結果」工作檯：每個問題的答案直接以完整的結果呈現，使用者逐一決定要不要留。

```
┌ 大腦：[deepagents · gemini-2.5-flash ▾]  session 8c1e  L0  [新對話] ────────────┐
├─────────────────────┬──────────────────────────────────────────────────────────┤
│ 對話                 │ 本次分析結果 · 3 個 · 未儲存 2     [全部｜未儲存｜已儲存] │
│ 你：華生知道真相的…  │ ┌ 結果 A · 未儲存 · L3 · 臨時組合 CH5＋MY1 ───────────┐ │
│ › run_method CH5     │ │ 誰知道同伴的來歷？  [存成筆記][另存方法論][捨棄]   │ │
│ 大腦：讀者早兩章……   │ │ [view：knowledge_matrix]  │ 結論（可改）           │ │
│ [→ 結果 A]           │ │                           │ 引用的證據 · 6         │ │
│ 你：那讀者被誤導到…  │ │ 怎麼得出的：run_method → get_run → show_view [重跑]│ │
│ [→ 結果 B]           │ └──────────────────────────────────────────────────┘ │
│ ┌ 寫入確認 ────────┐ │ ┌ 結果 B · 未儲存 … （同上結構）─────────────────────┐ │
│ │ 允許／拒絕       │ │ └──────────────────────────────────────────────────┘ │
│ └─────────────────┘ │ ▸ 結果 C · 已存成筆記 · 線索公平嗎？   在筆記中開啟    │
│ [輸入問題……][送出]   │                                                        │
└─────────────────────┴──────────────────────────────────────────────────────────┘
```

- **一個問題＝一個結果**：同一輪（`turnId`）的 `show_view` 與 `create_note` 草稿，在右側組成一個結果：view、可改的結論、引用的證據、怎麼得出的（該輪的工具呼叫）。對話裡只留旁白與「→ 結果 A」的連結。
- **使用者決定去留**：每個結果有三個動作。
  - **存成筆記**：走 N-06c（`origin=draft`），按下即人工審核（01 §5）。
  - **另存方法論**：把這一輪的工具呼叫順序存成使用者方法論（N-07e，`fromSession`）；與存成筆記是兩件事，可以都做。
  - **捨棄**：草稿標 `discarded`（N-10k）。
- **沒存的結果**：只是一次分析結果，下次重跑同一個分析就被取代；畫面上明寫這點。已存的收合成一行，連到筆記。
- **取用既有結果**：大腦可以用 `get_run` 拿已跑過的結果卡，結果上標「取用結果卡 MY5」，不重跑、不花 token。
- 工具呼叫在對話中只顯示一行摘要；完整參數與回傳在開發者檢視的 trace。
- 大腦的文字只是旁白；結果的 view 與草稿都來自它寫進系統的 records（架構文件原則 3）。

## 4. View 目錄（`show_view` 的類型）

方法宣告的 `view` 與 agent 的 `show_view(view_type, data_ref)` 共用這張表。`data_ref` 是一個 run id 或一組 evidence id；view 自己向後端取資料，agent 不傳資料本體，也不寫 UI。

| view_type | 用在 | 呈現 |
| --- | --- | --- |
| `causal_graph` | EV2、EV1、EV3 | 事件 DAG，kernel 粗框、satellite 細框，依 `text_rank` 由左到右 |
| `character_arc` | CH2 | 每個角色一條章節橫軸，分段標 phase |
| `network` | CH4 | 力導向圖，依派系群聚；沿用既有圖譜頁的群聚手法 |
| `timeline_dual` | NS2、MY1 | 上下兩軌：敘述順序與故事順序（MY1 換成「犯罪的故事」與「調查的故事」），連線表示對應 |
| `tension_lines` | TM1、TM2 | 每條張力線一列，章節上的強度 |
| `theme_card` | TM3 | 主題命題、Frye mythos、Booker plot、支撐的張力線 |
| `symbol_trend` | SY1 | 意象的章節分布與意涵轉變 |
| `knowledge_matrix` | CH5 | 角色 × 章節：已知、未知、錯誤認知 |
| `fairness_matrix` | MY4 | 真相 × 章節：線索出現、是否讀者可見、是否誤導、揭曉點 |
| `suspect_matrix` | MY5 | 嫌疑人 × 線索熱圖＋逐章嫌疑分數折線 |
| `stage_strip` | NS1 | 12 階段沿章節排列，標 fit 強弱 |
| `label_card` | CH1、CH3、MY3、MY2 | 分類結果＋理由＋依據等級 |
| `evidence_list` | 任何類型 | 通用：證據列表＋引文，任何沒有專屬 view 的類型都能用 |

## 5. 大腦接法

三種設定，都走同一個 Agent Gateway 介面（架構文件的 `AgentBackend` Protocol），UI 只在大腦選單切換。

| 選項 | 適合 | 需要 | 原型優先 |
| --- | --- | --- | --- |
| 無大腦 | 只看自動結果卡、從「也可以問」點分析 | 只需 pipeline 模型（Gemini API key） | 必做 |
| deepagents ＋ Gemini | 預設大腦 | 同上；大腦模型可另設 | 必做 |
| Claude Code（ACP） | 使用者已有 Claude Code 訂閱 | 本機已安裝並登入 Claude Code、Node | 必做（架構文件原排在階段二，原型提前） |

Pipeline（入庫與方法）一律用 provider 設定，不經大腦；原型最少只設 Gemini。

### 5.1 deepagents

- 用 `deepagents.create_deep_agent(model=..., tools=..., system_prompt=..., skills=[...])`。
- MCP 工具用 `langchain-mcp-adapters` 的 `MultiServerMCPClient` 連 StorySphere 自己的 MCP server（HTTP transport），`get_tools()` 後傳進 `tools`。
- Skills 傳 session 工作目錄下的 skills 資料夾，由 Gateway 依題材挑選後複製進去。
- 權限 L0（架構文件）：deepagents 自帶的檔案工具只碰虛擬檔案系統；關掉 shell 類工具。
- 串流用 LangGraph 的 `astream_events`，Gateway 轉成 AgentEvent。

### 5.2 Claude Code（ACP）

- Gateway 以子 process 啟動 `npx -y @agentclientprotocol/claude-agent-acp`，Python 端用官方 `agent-client-protocol` SDK（`spawn_agent_process`）當 client。
- 建 session 時傳入 StorySphere MCP server（HTTP，帶本 session 的 token）。
- Skills 寫進 session 工作目錄的 `.claude/skills/`，cwd 設為該目錄（ACP 沒有傳 skill 的標準方法）。
- 關掉 Claude Code 自帶的 Bash、寫檔、抓網頁工具；ACP 的 permission request 一律轉成 UI 的確認事件。
- 使用者用官方流程登入，StorySphere 不碰憑證（架構文件的條款段落）。
- **開工前的 spike（沿用架構文件待辦）**：用最小 MCP server 確認 Python ACP client 能啟動 adapter、傳入 MCP、收到工具呼叫事件。spike 不通時的備案：改用 Claude Agent SDK（Python）做 vendor SDK adapter，介面不變。

### 5.3 大腦拿到什麼

| 給大腦的 | 內容 |
| --- | --- |
| system prompt | 角色說明、目前的書與題材、「只用 StorySphere 工具，不自己讀檔或上網」、「結論要存成證據才算數」 |
| MCP 工具 | 04 的工具清單；依 session 白名單 |
| skills | 原型兩份：`event-analysis`、`mystery-fair-play`（照架構文件的 skill 範例格式寫，只引用工具名） |

## 6. 設定頁的初次啟動測試

沿用架構文件：對每個設定好的模型跑連線、structured output（小 JSON schema）、延遲三項，列成表；哪項失敗就標出受影響的 task。原型再加一列「大腦」：

- deepagents：建一個 session，請它呼叫一次 `list_genre_elements`，確認工具呼叫成功。
- Claude Code：檢查 `npx` 與 adapter 可啟動、Claude Code 已登入，再做同樣的工具呼叫測試。
